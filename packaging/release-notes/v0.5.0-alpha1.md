# Doritrack v0.5.0-alpha1 — experimental protocol V5

This prerelease introduces authenticated USB-tethered and same-subnet Wi-Fi
input, with the latency and recovery fixes from the V5 audit.

## Downloads and setup

- Windows x64: extract `Doritrack-v0.5.0-alpha1-windows-x64.zip` and open
  `HolodoriUsbController.exe`.
- Android: install `Doritrack-v0.5.0-alpha1-android.apk` (Android 6.0 or newer).
- Linux x64: extract `Doritrack-v0.5.0-alpha1-linux-x64.tar.gz`; use the same
  standalone Android APK. See `Docs/LINUX_SETUP.md` for prerequisites.

Update the phone and host together. Select USB tethering or Wi-Fi/local network
on both, press Pair on both, enter the host's eight-step lane pattern on the
phone, and approve locally on the host. Then press Start. An older V5
development build does not understand this release's authenticated idle
controls. V4 is available only through explicit legacy USB selection.

## Changes

- Noise-authenticated identities and ChaCha20-Poly1305 records; every immediate
  copy and repair has its own nonce. Remote pairing confirmation cannot replace
  local host approval.
- Ordered full-contact snapshots preserve taps, holds, chords, slide history,
  and crossed lanes. Thumb mode transforms historical and current samples.
- Fixes Android Keystore IV generation for first-use pairing persistence.
- Authenticated Stop and 500 ms idle PING/PONG prevent abandoned peers from
  pinning the host. Idle traffic never extends the active-input watchdog.
- Removes the fixed 100 ms V5 live-recovery delay. Fresh authentication and a
  session-start CANCEL remain required after failure.
- Deadline-driven, bounded Android queues keep immediate pairs together and
  give overdue 2 ms repairs a turn between pairs. Send and receive use separate
  cipher locks; interface inspection runs outside the input path.
- Reused host buffers, inline contacts, a bounded reorder ring, and preallocated
  native key-event storage remove per-frame heap allocation. Disabled metrics
  no longer allocate 8 MiB of histograms.
- Production-loop fault tests replace the old encryption-only V5 timing check.

## Validation and experimental limits

Local optimized Windows loopback measured 0.047 ms healthy p99 and 2.951 ms
p99 with both immediate copies lost; the worst repair was 3.166 ms. All
measured cases were below the 8.333 ms target. Final OS acceptance was simulated;
these numbers do not establish physical phone-to-game latency or a V4/V5 speed
ratio. Full methodology and Linux results are in `Docs/LATENCY_VALIDATION.md`.

Windows/Linux Rust tests, strict Clippy, optimized builds, Android debug/release
builds and lint, and launcher tests/build passed locally. The tested host input
path allocates no Rust heap memory after setup, including maximum-contact
gestures, metrics, event encoding, and encrypted ACKs.

The APK is debug-signed for experimental testing. If Android rejects an update
because an older APK used a different signing key, uninstalling that old app
removes its settings and pairing; pair again after installing this release.
No phone was connected for the Keystore device test or a USB/Wi-Fi physical
soak. Those checks remain necessary before claiming universal physical latency.

This is an unofficial companion and is subject to the game's terms and
competitive rules. It uses ordinary OS input without modifying the game.
