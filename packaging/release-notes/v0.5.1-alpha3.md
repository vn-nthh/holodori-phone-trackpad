# Doritrack v0.5.1-alpha3 — Pressure calibration and diagnostics

Adds an optional keyboard-mode pressure filter to Android Preferences, off by
default. A live vertical pressure marker and draggable cutoff share one line.
Use the local test pad to compare light brushes with normal taps, then save a
cutoff that rejects unwanted contacts on your phone. Live pressure, last peak,
and observed range remain visible while calibrating. Test touches send no keys.

Each finger registers immediately when a sample reaches the cutoff and stays
registered until lift/cancel. Lower pressure during an accepted hold or slide
does not release it. Historical samples, independent finger ownership, and
latest-snapshot recovery remain intact. The meter runs only in Preferences;
gameplay adds no confirmation delay or rendering. Touch injection is unaffected.

Use a conservative cutoff: some valid taps start lightly, and phones with
constant pressure cannot distinguish brushes from intentional taps this way.

Install the phone and host from this release together. The new keyboard-only
contact flag is rejected by older V5 hosts; older V4 hosts ignore the filter.

## Session diagnostics

This prerelease also includes the diagnostics update. Enable **Diagnostics** in
Android Preferences before Start, then use **Diagnostic reports → Export** after
Stop to save the latest runs as a ZIP. Host reports include a readable summary
and structured JSON in the existing report folder. The offline
`tools/diagnostic_report.py` joins phone and host reports by session and sequence.

Reports distinguish current and historical samples, queue/send delays, repairs,
ACK progress, sink outcomes, discarded frames, recording gaps, and recovery.
Directional timing is reported as bounds with explicit uncertainty. Bounded
workers analyze numeric records off the gameplay path; reports are saved after
Stop. No coordinates, keys, pairing credentials, or network addresses are added
to the diagnostic event records. See `DIAGNOSTICS.md` and the synthetic example
reports for interpretation and limitations.
Desktop bundles include the diagnostic guide, synthetic examples, and the
offline report joiner (requires Python).

on your phone and PC; software loopback checks simulate final OS acceptance.
